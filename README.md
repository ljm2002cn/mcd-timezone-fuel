# 麦麦时差补给官 · mcd-timezone-fuel

> **别人帮你算"划不划算"，我帮你算"此刻该不该吃、吃什么、吃完不影响明天"。**

一个为**跨时区工作者**设计的 WorkBuddy Skill，基于麦当劳中国官方 MCP 数据的时区感知点餐决策助手。

---

## 😵 痛点：这不是"半夜想吃麦当劳"，是"半夜必须吃麦当劳"

北京时间凌晨 3 点，是纽约中午 3 点。这个时差让跨时区工作者的进食时刻和本地人完全错开，于是有两个具体问题：

**问题一：决策失焦。**
深夜打开外卖，能选的只有"当前时段在售"那几样——通常是重油炸物。你看不到全菜单，也拿不到最划算的组合，只能将就。

**问题二：代谢错配。**
在错误的生物钟时点吃重油重钠的餐，第二天上午上班像没电。而夜里在售的偏偏就是高油高钠那几样。

**现有方案的盲区：** 帮你"算钱"的工具很多，帮你"算时段"的一个没有。

---

## 🎯 麦麦时差补给官做什么

它把「时区」当作**第一决策维度**，而不是一句附加说明。

### 1. 先建立时区坐标

调用 `now-time-info` 拿到当前时间，结合你所在的时区，算出：

```
本地时间：2026-10-25 03:12 (UTC+8)
远端时间：2026-10-24 15:12 (UTC-4)
时差：-12 小时 ｜ 对方时段：下午 → 抗困场景
```

没说明自己在哪个时区？它会先问你，不默认按 UTC+8 处理。

### 2. 按 8 个时段切换策略

| 时段 | 场景 | 策略 |
|---|---|---|
| 05:00–09:00 | 刚醒 / 早餐 | 轻负担，醒神组合 |
| 09:00–12:00 | 开工 | 标准正餐 |
| 12:00–14:00 | 午休 | 常规午餐，可叠券 |
| 14:00–17:00 | 犯困 | 低糖高蛋白抗困组合 |
| 17:00–20:00 | 下班 / 晚餐 | 常规正餐 |
| 20:00–23:00 | 收尾 | 轻食为主 |
| **23:00–05:00** | **熬夜 / 值班** | **控油控钠优先，禁止重油炸物** |
| 05:00 前 | 倒班 / 失眠 | 最轻量，避高咖啡因与高钠 |

深夜档会**强制**走轻负担路线，不是又摆一张营养表给你自己判断。

### 3. 三档方案 + 官方核价

```
A档 · 轻负担（深夜首选）  相对低钠低脂，撑住接下来 3–4 小时
B档 · 均衡              日常推荐
C档 · 放纵              想 reward 自己时（明确标注取舍，不隐藏代价）
```

每档都带 **MCP 返回的**热量与钠参考值、**真实可用**的券、以及「为什么适合这个时段」的一句话理由。最后用 `calculate-price` 官方核价：

```
原价 ¥XX  →  优惠 -¥XX  →  实付 ¥XX（含配送费 ¥XX）
```

### 4. 跨时区代点餐

帮纽约同事点午餐？它会走完整链路：查你的收货地址 → 查**那个地址**可配送的门店 → 拉**那家门店**的菜单（不同门店在售菜品不一样，绝不套用你自己门店的）→ 按对方当地时段选品 → 核价 → 你确认后下单。

地址数据只在会话内使用，**不落盘、不进仓库**。

## 🛡️ 数据真实性：每一条都有出处

这是本项目最较真的地方。

| 数据类型 | 来源工具 | 核验方式 |
|---|---|---|
| 当前时间 | `now-time-info` | MCP 实时返回 |
| 在售菜单 | `query-meals` / `query-meal-detail` | MCP 实时返回，按门店区分 |
| 营养成分 | `list-nutrition-foods` | MCP 返回值，仅作相对比较 |
| 优惠券 | `available-coupons` / `query-my-coupons` / `query-store-coupons` | MCP 实时返回 |
| 价格 | `calculate-price` | **官方核价**结果 |
| 门店 | `query-nearby-stores` / `delivery-query-stores` | MCP 实时返回 |
| 营销活动 | `campaign-calendar` | MCP 当月活动日历 |

**规则：没通过对应工具取得的数据，一律标注 `[待 MCP 核验]`，绝不用常识或记忆填补。**

不会出现"麦辣鸡腿堡约 21 元""约 520 千卡"这种看起来很合理的编造数字。MCP 报 401/403/429 时，它会如实告诉你拿不到实时数据并给降级路径，而不是拿静态知识冒充实时结果。

## 📦 安装

### 前置条件

1. 申请麦当劳 MCP Token
   访问 <https://open.mcd.cn/mcp> → 手机号登录 → 右上角「控制台」→「激活」→ 同意服务协议 → 复制 Token
2. WorkBuddy 支持 Streamable HTTP 传输协议

### 配置 MCP

编辑 `~/.workbuddy/mcp.json`，合并以下内容（**不要覆盖已有 server**）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

并设置环境变量：

```bash
export MCD_MCP_TOKEN="你的实际Token"
```

也可以在 WorkBuddy 界面中操作：左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置MCP】→ 填入上述 JSON → 保存 → 启用 `mcd-mcp`。

> 配置后需在连接器管理页右上角的自定义连接器入口点击「信任」，新 MCP 才会生效。

仓库中的 [`mcp-config.example.json`](./mcp-config.example.json) 是脱敏示例，仅含环境变量占位符。

### 安装 Skill

把本仓库的 `SKILL.md` 放入你的 Skills 目录，或直接在 WorkBuddy 中引用本目录即可。

## 💬 使用示例

**深夜加班**

> 我在上海，现在凌晨 3 点，楼下只有麦当劳，帮我配一份能撑住明天上午的

→ 输出时区坐标 → 命中深夜策略 → 三档方案（A 档强制轻负担）→ 官方核价 → 一句话结论

**跨时区代点**

> 帮我给纽约的同事点一份午餐，他现在应该在办公室

→ 换算纽约时段 → 查地址对应门店 → 拉该店菜单 → 按对方时段选品 → 核价 → 确认后下单

**下午抗困**

> 三点半了困得不行，吃点麦能顶到下班吗

→ 命中「下午犯困」策略 → 低糖高蛋白组合 → 说明为什么不是汉堡

**券与核价**

> 我手上有券，帮我算下这顿到底多少钱

→ 查三处券 → `calculate-price` 官方核价 → 输出原价→优惠→实付全链路；券超预算时明确提示并给不超预算备选

## 🎁 它和榜单上其他项目有什么不同

现有参赛作品大多集中在**通用省钱、预算算账、活动日历、营养计算**四个方向。本项目：

1. **时区是第一维度，不是附加信息**——别的作品假设你和门店在同一时区，这里时差是策略主轴，定义了 8 个时段的独立规则。
2. **时段决定策略，而非只做数据展示**——深夜档禁止重油炸物，是基于真实营养数据的**约束**，不是又一张营养表格。
3. **覆盖跨时区代点餐**——地址→门店→菜单→下单完整链路，地址不落盘。
4. **输出带核验状态**——每项数据标注来源工具，未核验的显式标 `[待 MCP 核验]`。
